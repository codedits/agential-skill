# Web Research Workflow

When and how to search the web to resolve uncertainty and incorporate current design or technical patterns.

---

## When to Search

1. **Uncertain or breaking API changes.** A library has a major version upgrade (e.g. Next.js App Router, Tailwind v4).
2. **Ambiguous errors.** An error message lacks obvious context.
3. **Design inspiration.** The user requests a modern dashboard or landing page and needs current aesthetics.
4. **Unfamiliar stacks.** Working with a tool or SDK the model hasn't encountered frequently.

---

## Best Practices

### Formulate precise queries
- Bad: `how to fix nodejs error`
- Good: `Node.js 22 crypto.timingSafeEqual ERR_INVALID_ARG_TYPE solution`

### Prioritize authoritative sources
- Official documentation and RFCs
- GitHub issues, discussions, and releases
- Verified technical engineering blogs

### Translate findings directly
Synthesize into code. Do not paste lengthy search summaries unless the user asked for research notes.
